# Runtime ownership (#1047): scope and test map

Audit base: `891d94f7` (tree `9a40c37f93eb27604c0573de40030c2a5b978459`, merge of main into
`feat/m17-runtime-ownership-baseline-941`). This page is part of the head that fixes the findings
below, so it cannot name that head; the exact head, tree and per-command results are in the review
hand-off and the PR description.

open. A passing test qualifies the named behavior only. No row claims a physical device, a live
provider, hosted CI, hosted PostgreSQL/Restate or PostgreSQL.

## 4. Incomplete milestones (not done, deliberately)

1. **Production controller wire (#1023).** `AcpRemoteWire` has no production implementation: nothing
   sends sealed commands or inventory requests through `apps/runtime-gateway` to a device, and the
   repository holds no node agent that answers them. Closing it needs a design decision, not wiring:
   a sealed device reply is a per-command artifact the gateway protocol (`runtime.acp-remote-sealed`)
   must carry back, and `RuntimeCommandArtifactVerifier` allows one result artifact per attempt.
   Recommended: gateway-owned wire with a per-command reply artifact. Not started in this PR.
2. **#1123 parent-plan repository dependency.** `DurableChildRuntimeBudgetAdmission({ store, plans })`
   exists only in draft CP #1123 (open, unmerged, head `1f8d735a`) and no composition root in this
   tree builds `CanonicalDelegationRuntimeBridge`, so there is nothing to wire it into. When both
   exist, the root passes the usage store its child allocator opens budgets in and the same
   `ExecutionPlanRepository` the bridge reads, with `.reserve` unwrapped, per the contract in
   `docs/usage-ledger.md` on #1123. No change to #1123 is needed.
3. **Hosted composition.** `PostgresPersistenceProvider` and the PostgreSQL device state are
   test-qualified only; no Hosted composition constructs a device endpoint.
4. **Credential sources.** Local composition has no production runtime-node credential source, so
   SQLite runtime-command settlement and event effects fail closed there.
5. **Context-command and `hello` fences.** `SqliteContextCommandRepository` settlement and the
   reconnect `hello` retained-outcome applier carry no credential fence.
6. **Inventory in `channel-authenticated` mode** trusts the authenticated channel and the wire that
   selects the mode; no request nonce or device signature. The composition, not the wire, should
   choose the mode.
7. **Device signing-key rotation.** State is scoped by device key id; rotation starts a fresh fence and
   ledger and revocation notices do not name the key. A procedure is not defined.
8. **Compact ledger records are never deleted.** Duplicate protection must survive window expiry, so a
   closed-window claim is compacted, not removed: one small record per command for the life of the
   route, with a recorded exchange reduced to `outcome_uncertain`. A retention horizon needs a
   controller-side command-id epoch or watermark; not designed.
9. **PostgreSQL record details.** A NUL character in a recorded outcome cannot be stored in `jsonb`
   (the outcome stays pending and replays as `outcome_uncertain`), and the provider does not apply
   SQLite's record-size limit or ordering. The 0073 constraints take a full-table lock.
10. **Not run anywhere:** hosted CI, hosted PostgreSQL/Restate, PostgreSQL DDL probe, native device, live
    provider, active cancellation stop, usage settlement.
